# NEO MERZ — Telegram Casino Mini App

Каркас проекта по ТЗ. Готово: Этап 0-1 (фундамент + Слоты/Кости/Мины + AdsGram),
Этап 2 (Рулетка/Колесо/Краш), Этап 3 (Блэкджек/Покер), Этап 4 (рефералы/
лидерборды/достижения), Этап 5 (Турниры + Stars Payments для VIP/косметики +
отдельная админ-панель), Этап 6 (звук/анимации, антифрод рекламных наград,
нагрузочное тестирование — админ-панель с ролями была построена ещё на Этапе 5),
бот-слой (grammY).

## Что уже реализовано

**Backend** (`/backend`, Fastify + TypeScript + Prisma/PostgreSQL):
- Авторизация через Telegram `initData` (HMAC-проверка подписи, создание пользователя при первом входе, поддержка `ref_<id>` в `start_param`).
- Экономика: баланс, история транзакций, дневной бонус со стриком (раздел 1.3, 2.4 ТЗ).
- Восемь игр, вся логика и RNG (`crypto.randomInt`) строго на backend: Кости, Мины, Слоты, Рулетка, Колесо фортуны, Краш, Блэкджек, Видео-покер.
- **AdsGram**: два эндпоинта (`ad-coin-reward`, `bonus-chest`) с идемпотентностью по `adsgramImpressionId` и серверным rate-limit через Redis. Лимиты/награда теперь читаются из БД (`AdSettings`, singleton), а не из `.env` — редактируются из админ-панели без деплоя (раздел 5 ТЗ).
- Рефералы (2 уровня, бонус за активацию), еженедельный лидерборд (с опцией анонимности), достижения с прогрессом и клеймом наград (раздел 1.6-1.7 ТЗ).
- **Турниры** (раздел 1.5 ТЗ, `modules/tournaments/tournamentService.ts`): лидерборд по метрике (сумма выигрыша / сумма ставок / число раундов) за окно `startAt..endAt`, считается "на лету" из уже существующих `Transaction`/`GameSession` — без отдельной записи на каждую ставку. Финализация — снэпшот в `TournamentScore` + автовыплата призов по местам, идемпотентно.
- **Админ-панель API** (`/api/admin/*`, `routes/adminRoutes.ts`): отдельная авторизация по логину/паролю (JWT, `ADMIN_JWT_SECRET`, НЕ Telegram initData), три роли — `SUPERADMIN` / `FINANCE` / `MODERATOR` — с разным доступом к роутам (см. `middleware/adminAuth.ts`). Покрывает: дашборд (DAU/MAU, активность по играм, доход — частично заглушки, см. ниже), турниры (создание/финализация), пользователи (поиск, бан, ручная корректировка баланса с обязательной причиной), game-configs (шансы игр — только SUPERADMIN, с логированием каждого изменения), каталог косметики, рассылки (сегментация по VIP-тиру/активности + отложенная отправка), лог действий админов.
- Схема БД (Prisma) обновлена под Этап 5: `Tournament`, `TournamentScore`, `CosmeticItem`, `UserCosmetic`, `AdSettings`, `Broadcast`, `AdminUser`, `AdminLog`, `StarsPayment`; под Этап 6 — `AdView.suspicious` (антифрод).
- **Stars Payments** (раздел 2.2 ТЗ, `modules/shop/starsPaymentService.ts`): VIP-подписка (5 тиров, каталог цен/длительности/бенефитов в `config.shop.vipTiers`) и покупка косметики через Telegram Bot Payments API. Backend создаёт инвойс-ссылку (`createInvoiceLink`, валюта `XTR`) — прямой HTTPS-вызов Bot API, без grammY. Идемпотентность выдачи товара — через `StarsPayment.status` (compare-and-swap в `$transaction`) + уникальный `telegramPaymentChargeId`, так что повторная доставка `successful_payment` от Telegram не выдаст покупку дважды. VIP теперь реально даёт то, что обещано в разделе 1.2 ТЗ: множитель к дневному бонусу (`economyService.claimDailyBonus`) и бонус к дневному лимиту рекламы (`adsService.claimCoinRewardAd`).
- **Антифрод рекламных наград** (раздел 6 ТЗ, `lib/antifraud.ts`): минимальный интервал между claim'ами одного игрока — жёсткая блокировка при физически невозможной скорости (`AD_ANTIFRAUD_HARD_MIN_SECONDS`) и мягкая пометка `AdView.suspicious=true` при подозрительной скорости (`AD_ANTIFRAUD_SOFT_MIN_SECONDS`), без блокировки самой награды (чтобы не портить UX реальным игрокам с пограничным таймингом). Помеченные показы видны в админке (раздел «Антифрод», роли SUPERADMIN/MODERATOR) для ручного решения бан/пропустить.
- **Нагрузочное тестирование** (раздел 6 ТЗ, `backend/loadtest/`): k6-сценарий с реалистичным миксом трафика (игры/дневной бонус/реклама/турниры/магазин) + генератор настоящих подписанных Telegram `initData` для синтетических пользователей (проверено — HMAC совпадает с `verifyTelegramInitData`). Скрипты не запускались против живого стека в этой среде (нет сети) — см. `loadtest/README.md`, там же честный разбор вероятных узких мест по коду (непроцессовая кластеризация, ненастроенный пул Prisma, live-агрегация лидерборда/турниров, общий Redis rate-limiter) и объяснение, почему WebSocket-стрим Краша при этом хорошо масштабируется горизонтально.

**Frontend / Mini App** (`/frontend`, React + Vite + Zustand):
- Тема/палитра точно по ТЗ (CSS-переменные в `src/styles/theme.css`).
- i18n — `src/i18n/ru.json` + `en.json`, переключение языка через `useLocaleStore`.
- Экраны: Лобби, 8 игр, "Заработать монеты", Профиль, Лидерборд, Турниры, **Магазин** (новое — VIP-тиры + косметика за Stars, раздел 2.2 ТЗ, открывает `Telegram.WebApp.openInvoice()`).
- Хук `useAdsgram`, иконки `lucide-react`, анимация на Framer Motion во всех 8 играх (Этап 6 добавил spring pop-in для Костей/Краша/Блэкджека/Покера — раньше без анимации, у остальных уже была).
- **Звук** (Этап 6, раздел 6 ТЗ, `src/lib/sound.ts`): процедурные Web Audio эффекты (клик/ставка/выигрыш/большой выигрыш/проигрыш/монеты/карта) вместо скачанных mp3 — нет ни лицензионных рисков, ни лишнего веса бандла. Тумблер mute в `BalanceBar` (виден на всех экранах), состояние в `localStorage` через `useSoundStore`.

**Админ-панель — отдельное SPA** (`/admin`, React + Vite, БЕЗ react-router — тот же приём "page-state" в `App.tsx`, что и в Mini App, чтобы не тащить лишнюю зависимость):
- Экран логина (логин/пароль → JWT, хранится в `localStorage`).
- Sidebar с пунктами, отфильтрованными по роли текущего админа.
- Дашборд (теперь с реальным доходом Stars и счётчиком помеченных антифродом показов рекламы), Турниры (список/создание/финализация с выплатой призов), Пользователи (поиск, карточка с историей транзакций, бан/разбан, корректировка баланса), Косметика (каталог), Рассылки (сегментация + превью размера аудитории + отложенная отправка), Игры и лимиты (шансы игр + рекламные лимиты, только SUPERADMIN), **Антифрод** (Этап 6 — список показов рекламы, помеченных антифродом, с быстрым баном), Логи.
- Своя палитра — те же CSS-переменные, что у Mini App, но десктопная раскладка (сайдбар + таблицы).

**Bot layer** (`/bot`, grammY):
- `/start` с обработкой deep-link `ref_<id>`, `/help`.
- Фоновая джоба — уведомление "дневной бонус готов".
- **Отправка рассылок** (`broadcastSender.ts`): поллинг `Broadcast` со статусом `SCHEDULED`, чья `scheduledAt` уже наступила → считает сегмент получателей и рассылает через Bot API, помечает `SENT` со счётчиком доставленных. Админка только создаёт запись и считает сегмент — сама отправка требует Bot API, который есть только в bot-слое.
- **Stars-платежи** (`payments.ts`, новое): принимает `pre_checkout_query` (валидирует через backend, отвечает в течение 10с — требование Bot API) и `successful_payment` (просит backend завершить покупку и выдать VIP/косметику). Весь бизнес-смысл — на backend; бот только транслирует два Telegram-апдейта, которые может получить только он.

## Bootstrap первого админа

Панель защищена логином/паролем, поэтому нужен хотя бы один `AdminUser` в БД, чтобы вообще войти:

```bash
cd backend
# .env: задать ADMIN_BOOTSTRAP_LOGIN и ADMIN_BOOTSTRAP_PASSWORD
npm run seed
```

`seed.ts` идемпотентно создаёт **одного** superadmin-пользователя с этим логином/паролем, если
пользователя с таким логином ещё нет в БД (повторный запуск seed не перезатирает уже
сменённый пароль). После первого входа рекомендуется сменить пароль и/или завести именных
админов прямо из панели, а `ADMIN_BOOTSTRAP_*` из `.env` — убрать.

## Что НЕ входит в этот каркас (следующие шаги)

- **Сегментация рассылок по языку** — раздел 5 ТЗ упоминает её, но `User` пока не хранит выбранную локаль (i18n во фронтенде — чисто клиентский `zustand`-store, ничего не шлёт на backend). Нужно завести `User.preferredLocale` + endpoint для его сохранения. Сегментация по VIP-тиру и активности уже работает.
- **Смена VIP-тира "на лету"** — если у игрока уже активен один тир и он покупает ДРУГОЙ, срок подписки считается заново от текущего момента (не пытаемся пересчитать "остаток" старого тира в днях нового). Продление ТОГО ЖЕ тира работает корректно (дни добавляются к текущему `vipExpiresAt`).
- **Refund/chargeback для Stars-платежей** — Bot API поддерживает `refundStarPayment`, но обработчик и админ-действие "вернуть звёзды" не реализованы; статус `StarsPayment.status="FAILED"` предусмотрен в схеме, но проставляется только при неудачной попытке создать инвойс, не при возврате уже оплаченного.
- **Ежедневная фоновая проверка истёкших VIP-подписок** — `vipTier` на `User` не сбрасывается в `NONE` автоматически по истечении `vipExpiresAt`; везде, где это важно (дневной бонус, лимит рекламы), проверка "`vipExpiresAt` в будущем" сделана на лету при каждом использовании, так что реального бага нет — но в профиле/админке тир может визуально показываться даже после истечения, пока не будет отдельной джобы или вычисляемого поля.
- Реальный доход от рекламы (eCPM/ad fill rate) на дашборде — заглушка, у нас нет доступа к кабинету AdsGram; вместо этого честно считаются "засчитанные показы" (нижняя граница объёма трафика, не доход).
- D1-retention на дашборде — грубая когортная оценка для MVP, не production-grade BI.
- Автоматический перевод турнира `SCHEDULED → ACTIVE` сделан лениво (при каждом `GET /tournaments`), а не отдельной cron-джобой/очередью — для MVP-нагрузки этого достаточно, полноценные Redis-очереди для турнирных пересчётов упомянуты в ТЗ как план на будущее.
- Серверный postback от AdsGram (сейчас — клиентский `show()` + серверные лимиты).
- **Нагрузочный тест не запускался.** `backend/loadtest/` содержит рабочий k6-скрипт и генератор подписанных `initData` (HMAC проверен вручную — совпадает с backend), но реальный прогон против живого стека требует сети/поднятой инфраструктуры, которых нет в среде разработки. Цифры P95/пропускной способности появятся только после того, как вы сами запустите `k6 run` — см. `loadtest/README.md`, включая разбор вероятных узких мест по коду.
- **Антифрод рекламы — эвристика скорости, не полноценная система.** Проверяется только минимальный интервал между claim'ами одного игрока (раздел 6 ТЗ); нет device fingerprinting, нет анализа паттернов по IP/устройству, нет автоматической блокировки (только пометка для ручного решения админом). Пороги (`AD_ANTIFRAUD_HARD_MIN_SECONDS`/`SOFT_MIN_SECONDS`) не откалиброваны под реальные данные — это стартовые значения, требующие подстройки после первых недель живого трафика.
- Полноценный WebGL/дизайн-полишинг анимаций (рулетка/колесо/краш выше уровня Framer Motion) и лицензированные звуковые эффекты (сейчас — процедурный Web Audio синтез, не студийные сэмплы) — возможный следующий шаг сверх Этапа 6, если потребуется более "премиальный" аудиовизуальный уровень.
- KYC/AML — не входит в MVP на play-money модели.

## Запуск локально

```bash
# 1. Инфраструктура
docker compose up -d          # Postgres + Redis

# 2. Backend
cd backend
cp .env.example .env          # TELEGRAM_BOT_TOKEN, ADMIN_JWT_SECRET, ADMIN_BOOTSTRAP_LOGIN/PASSWORD, INTERNAL_API_SECRET и остальные значения
npm install
npm run prisma:migrate
npm run seed                  # game-configs + AdSettings + bootstrap-admin
npm run dev                   # http://localhost:3000, админ-API — /api/admin/*

# 3. Frontend (Mini App)
cd ../frontend
cp .env.example .env
npm install
npm run dev                   # http://localhost:5173

# 4. Admin SPA
cd ../admin
cp .env.example .env          # VITE_ADMIN_API_BASE=http://localhost:3000/api/admin
npm install
npm run dev                   # http://localhost:5174

# 5. Bot (опционально для /start и уведомлений — но ОБЯЗАТЕЛЕН для покупок:
#    Telegram шлёт pre_checkout_query/successful_payment только боту, без него
#    Stars-платежи зависнут в PENDING на стороне Telegram)
cd ../bot
cp .env.example .env          # TELEGRAM_BOT_TOKEN, MINI_APP_URL, DATABASE_URL, BACKEND_INTERNAL_URL + INTERNAL_API_SECRET (совпадает с backend/.env)
npm install
npm run dev
```

Для реального теста внутри Telegram нужен HTTPS-домен (см. раздел 4 ТЗ) — на локали
Mini App можно тестировать через ngrok/Cloudflare Tunnel, направленный на порт 5173,
и зарегистрировать этот URL в @BotFather как Web App URL. Админ-панель (порт 5174) в
Telegram не встраивается — это обычный браузерный SPA, HTTPS туда нужен только для прода.

Нагрузочное тестирование — отдельно, см. `backend/loadtest/README.md` (k6 + генератор
подписанных Telegram `initData`; скрипты не запускались против живого стека в этой среде,
это рабочий инструмент, а не отчёт с цифрами).

## Про визуальные ассеты

По вашему ответу на этот вопрос — конкретных референсов/лого пока нет. Вместо того чтобы
брать готовые казино-иконки/арт из открытого поиска (риск копирайта + случайная
стилистика, не сочетающаяся с MRKT-референсом), сейчас использую:
- `lucide-react` — открытая (MIT) библиотека иконок, уже даёт нужный минималистичный стиль;
- эмодзи как временную заглушку для символов слотов — легко заменить на спрайты.

Логотип/финальный арт слотов/колеса лучше либо заказать у дизайнера под референс MRKT,
либо сгенерировать отдельно (могу подготовить промпты под генерацию, если нужно).

## Открытые вопросы, которые всё ещё влияют на калибровку

- Реальный eCPM из вашего AdsGram-кабинета — как только будут первые данные, можно
  пересчитать рекламные лимиты/награду прямо из админ-панели (раздел «Игры и лимиты»),
  без деплоя.
- Расчёт баланса (раздел 2.4) принят как стартовая точка — все параметры вынесены в
  `GameConfig`/админку, калибровка после первой когорты не требует переразвёртывания кода.
- Призовые фонды турниров задаются вручную при создании турнира в админке — стартовые
  значения (сколько монет за 1/2/3 место) нужно откалибровать под реальный размер аудитории.
